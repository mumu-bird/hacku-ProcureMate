# 人工 / 代理采购对照：现场执行材料

目标至少五名同学，匿名 P01–P05。官方赛题要求人工路线的步骤、时间、费用对照，未指定五人；五人是本项目计划。当前没有已完成记录，CSV 数值留空。

## 同一任务

为 10 位年轻同事各采购一件现成饮水杯/瓶，用途是活动礼品，偏好实用简约；公司现金总预算 HK$2,500，统一香港办公室收货。只用 `data/catalog.json` 的礼品商品和同一份 `data/merchant-policy.json`，不用积分、优惠券或个人奖励。两条路线都采用保存的价格快照，不在其中一条路线换成实时价格。

共同计时终点：选出一个符合人数、预算、品类的方案，提交完整含费支出与授权边界，说明是否应继续付款。测试的是选品和授权准备的角色任务，**不是实际商户购物耗时**。代理后续测试付款可另外记录，不与人工只填方案的时间混在一起。

人工路线：打开商品来源/目录快照，手算商品数量与价格，查询派送规则，填写预算、品类、商户、有效期，说明是否可付款。可以使用日常计算器。代理路线：登录已准备好的工作区，输入同一任务，生成方案，选定方案并填写授权卡；以授权卡准备完成作为同一计时终点，不提前提交模拟付款。

## 安排与记录

1. P01、P03、P05 先人工，P02、P04 先代理；第二次重复相同任务。练习效应仍存在，报告中明确说明。
2. 同一电脑和目录快照；负责人预先排除登录/工具安装时间。推荐配对页面为每位参与者创建独立会话，不复用别人的方案或答案。保留同一个数据库以汇总全部参与者，不能逐人清空；该页面只准备采购方案，不执行付款或复用工作台授权。
3. 从参与者第一次操作任务开始，到提交可核对方案停止。原始录屏、计时或观察记录本地保留；只公开匿名汇总。
4. 一个步骤指有独立目的的操作，如查看商品、计算数量、查派送费、比较候选、填写授权；键入一个字符不计一步。两条路线使用同一定义。
5. 记录数量不足、漏算费用、超预算、越过品类或未经授权付款等错误。介入帮助、卡顿、放弃和任务超时必须记备注，不能只保留成功者。
6. `cost_hkd` 是所选方案的公司现金完整支出；任务不确定时留空并说明原因，不能当作零费用。不要把时间差换算成未经观察的工资或企业节省。

## 汇总与报告

每人一对记录，共十行。展示全部配对的时间、步骤、费用和错误；可用中位数，并同时显示样本量、任务条件与先后顺序。完成少于五人时如实注明，不能把软件测试运行速度当成真人时间。

推荐直接导出配对页面的结果，不再把同一批参与者重复录入“执行记录”的旧手工表。若采用线下计时，则用空白 CSV 保存任务编号、测试顺序、完成状态及原始观察依据，并单独报告。更新路演第六页时，说明这是学生角色任务的原型可用性观察。它不能证明企业需求、付费意愿、真实支付成功率或长期节省。

## 推荐使用计时配对页面

1. `npm run dev`，在工作台以负责人登录，进入“执行记录 → 开展计时配对测试”，或打开 `http://127.0.0.1:3000/study`。主持人需要确认有实际参与者，并已同意匿名记录；不要用开发者或自动化脚本冒充同学。
2. 编号 P01–P05。页面默认奇数人工先做、偶数代理先做；创建后顺序固定，匿名编号不能重建覆盖。主持人先解释共同终点与步骤定义，不告诉参与者商品选择和费用答案。
3. 开始第一条路线后计时。人工自行查看固定目录、费用来源并核算；代理通过同页按钮生成方案。两条路线在同一张表提交商品、数量、完整费用和授权边界；都不付款。
4. 主持人记录完整目的步骤数（包括计算器、外部商品页面等），填写帮助次数与备注。页面自动记录部分有明确目的的操作，但它不等于完整步骤数，不能把未观察当零步骤。服务端时间包含模型等待和操作；离开页面后仍计时，暂停、卡顿须记录备注。
5. 点击“封存任务结果”，错误答案也保存，不能再改写。放弃或中断填写原因并封存，不能删除失败者。第一条路线的答案校验在第二条结束后才显示，以减少提前反馈影响；熟悉同一任务的练习效应仍然存在。
6. 按既定顺序完成第二条路线。两条路线共用商品与运费快照摘要；目录变更时，代理停止生成新方案，须记录中断。
7. 导出 `procuremate-human-study.json`，本地保留观察笔记或录屏依据。报告包含所有匿名会话、原始答案、时间、观察步骤、部分页面操作、帮助与错误。不同快照分组；配对提交的统计包括错误提交，并同时显示合规数和放弃数，不得直接宣传为成功效率。

主持人确认不等于独立身份核验。当前数据库尚无真人记录；核心测试和浏览器测试使用独立临时数据库，测试中 P90–P98 全部是自动化夹具，不能写入真人结果或路演指标。旧的手工录入表仍可保存外部观察，但未与配对页面合并为重复参与者。
